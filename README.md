# More Bases Views

[English](README_EN.md) | 简体中文

More Bases Views 是一个面向 [Obsidian](https://obsidian.md/) Bases 的多视图插件, 为同一组数据库条目提供书籍, 项目, 地图, 卡牌与索引等不同展示方式.

*让数据库按照内容本身的形态呈现.*

插件保留 Bases 的筛选, 排序, 分组和属性映射能力, 并在此基础上补充主题化界面, 卡片交互, 属性编辑, HTML 导出与大数据量虚拟渲染.

## 视图

| 视图 | 适用内容 | 主要能力 |
| --- | --- | --- |
| **书籍** | 图书, 教材, 文献集 | 立体封面与同图书脊, 阅读状态, 附件打开 |
| **论文** | 论文与研究资料 | 标题, 作者, 页数, 阅读状态与附件入口 |
| **项目** | GitHub 项目与开发任务 | 仓库指标, 公开状态, 开发状态与任务清单 |
| **课程** | 课程与成绩 | 照片, 得分, 可配置满分与成绩色彩 |
| **影视** | 剧集, 动画与综合媒体 | 海报, 集数, 时长, 类型, 日期与评分 |
| **电影** | 电影收藏 | 电影卡片布局, 海报比例与评分信息 |
| **游戏** | 游戏收藏 | 封面, 类型, 发行日期与可编辑评分 |
| **卡牌** | 自定义收藏卡 | 自定义宽高比, 金色边框, 材质与放大交互 |
| **干员** | 明日方舟风格角色资料 | 普通/隐藏立绘, 职业, 阵营, 星级与立绘定位 |
| **炉石** | 炉石风格卡牌资料 | 多卡牌类型, 实时编辑器, 相关卡牌与完整卡面交互 |
| **地图** | 地点与地理资料 | MapLibre 地图, 自定义瓦片, 标记图标, 颜色与弹出卡片 |
| **名人** | 人物与照片收藏 | 木质相框, 卡纸宽度与照片展示 |
| **评价** | 排名与分级 | Tier List, 分级下钻, 拖拽评分与自动滚动 |
| **索引** | 大型笔记索引 | 原生文件树风格分类, 搜索, 虚拟列表与标签管理 |

## 共通能力

### Bases 集成

- 直接使用 Bases 的筛选, 排序和分组结果.
- 在视图设置中将卡面字段映射到任意 Bases 属性.
- 可调整卡片宽度, 图片比例和视图专属选项.
- 支持独立 `.base` 文件与适用的嵌入式 Bases 场景.
- 官方表格视图可启用批量属性管理器, 在当前筛选结果内预览并执行属性添加, 更新, 删除, 替换与重命名.

### 文件打开与编辑

- 支持在当前标签页, 新标签页或 Modal 中打开 Markdown 笔记.
- 卡牌, 炉石和干员视图提供适合卡面的放大与编辑交互.
- 可写入属性使用即时保存, 并在保存前检查笔记是否已被其他操作修改.
- 书籍和论文视图可在 Obsidian 或系统默认应用中打开附件.

### 性能与导出

- 卡片型视图使用虚拟网格, 只保留当前视口附近的卡片.
- 图片加载, Canvas 绘制与高成本任务按需执行.
- 多数卡片视图提供 **导出 HTML...**, 导出文件会内联图片和样式, 保留适用的 hover, 放大与切换交互.
- 导出直接读取当前 Bases 查询结果, 不要求先滚动并加载完整视图.

## 重点视图

### 项目视图

项目视图使用终端卡片展示 GitHub 仓库信息. 设置项目地址属性后, 可显示版本, Stars, 下载量, Issues, Pull requests, 许可证, 主要语言和最近提交等指标.

- **Status**: 标记项目处于开发中或阶段完成.
- **Public**: 标记项目是否公开; 私有项目不显示不存在的在线指标.
- **任务**: 在项目笔记中管理未完成与已完成任务.
- 标题栏 GitHub 图标可直接打开仓库页面.

### 索引视图

索引视图将数据库条目组织为接近 Obsidian 原生文件列表的双栏界面.

- 左侧按属性生成可折叠分类树, 支持拖拽调整分类顺序.
- 右侧使用虚拟列表显示匹配笔记.
- 支持标题, 分类和属性搜索.
- 可打开笔记, 编辑标签或删除文件.

### 地图视图

地图视图根据坐标属性生成地图标记, 支持浅色与深色瓦片地址, 中心坐标, 缩放范围和嵌入高度.

- 标记可映射 Lucide 图标, 颜色, 标题与封面属性.
- 点击标记显示笔记摘要卡片.
- 默认地图来源为 OpenStreetMap 与 CARTO; 也可以改为自定义瓦片服务.

### 卡牌视图

- 使用正面图片属性生成自定义比例卡牌.
- 单击放大时再次单击可打开对应笔记; 也可以关闭单击放大并直接打开笔记.
- 材质包含 **无**, **随机** 与多种动态光效; **无** 不加载任何材质层.
- 卡牌放大期间锁定当前滚动位置, 移出卡面后平滑复位.

### 干员视图

- 支持普通模式和隐藏模式, 两种模式分别读取对应立绘与定位属性.
- 立绘可使用单个图片双链或双链列表, 并通过拖拽和滚轮调整位置与缩放.
- 职业和阵营均使用“主类别 + 分支”编辑结构, 属性仍保存最终显示值, 兼容旧笔记.
- 右键卡牌打开编辑 Modal; 当前视图模式决定编辑普通立绘或隐藏立绘.
- 支持职业, 阵营和多张立绘轮换, 星级框体以及独立 HTML 导出交互.

立绘定位使用文本格式:

```yaml
立绘定位: "[50,0,1.48]"
隐藏立绘定位: "[50,0,1.48]; [10,-5,1.2]"
```

三个数字依次表示横向位置, 纵向位置和缩放倍率. 多张立绘的位置使用分号分隔并按顺序对应.

### 炉石视图

炉石视图支持传统对战与酒馆战棋, 可生成随从, 英雄, 法术, 武器和地标等卡面.

- 支持普通, 金卡, 钻石卡与异画外观, 双职业, 稀有度, 种族或派系, 消耗, 属性值和旗帜或符文.
- 传统对战消耗支持法力水晶, 生命值, 残骸与护甲值; 酒馆战棋支持铸币和时光标记.
- 英雄可以展开独立技能框; 趣闻在卡牌放大时从右侧展开.
- 相关卡牌可收纳到父卡片, 放大后从卡面下方打开列表并悬停预览.
- 右键打开实时编辑 Modal, 可编辑字段并直接拖拽插画位置.
- 卡牌单击放大并翻转传说卡背, 再次单击打开笔记.
- 材质与卡牌视图共享视觉实现, 但两个拓展包彼此独立.

基础属性示例:

```yaml
卡名: 晨曦守护者
类型: 传统对战-随从
外观: 金卡
职业: [圣骑士]
稀有度: 传说
原画: "[[附件/守护者.png]]"
插画定位: "[50,0,1.48]"
消耗: 法力水晶-5
属性值: 4/8
种族: [龙]
描述: |-
  **圣盾, 嘲讽**
  在你的回合结束时, 为所有友方角色恢复 2 点生命值.
趣闻: 这段文字只在卡牌放大后显示.
```

字段名称可以自由设置, 只需在炉石视图设置中映射对应属性.

## 拓展包

卡牌, 干员和炉石视图使用版本绑定的单文件资源包, 避免将大量美术资源写入 `main.js`. 原始素材和生成后的 `.mbvpack` 均不属于开源仓库, 需要通过获得授权的独立渠道提供:

```text
view-packs/
├─ card.mbvpack
├─ operator.mbvpack
└─ hearthstone.mbvpack
```

- `card.mbvpack`: 卡牌材质资源.
- `operator.mbvpack`: 干员职业, 阵营, 星级与控制素材.
- `hearthstone.mbvpack`: 炉石卡框, 图标, 卡背及同版材质资源.
- 炉石包单独包含其使用的材质, 不依赖卡牌包.
- 拓展包必须与插件版本一致. 文件缺失, 损坏或版本不匹配时, 对应视图仍会保留并显示导入入口.
- 从视图导入 `.mbvpack` 后, 文件会写入插件目录下的 `view-packs/`.
- AGPL-3.0 仅覆盖公开源码; 私有素材与 `.mbvpack` 不在该许可证授权范围内.

## 使用方式

1. 创建或打开一个 `.base` 文件.
2. 在 Bases 工具栏中添加视图.
3. 选择 **书籍**, **项目**, **卡牌**, **炉石** 或其他 More Bases Views 视图.
4. 打开视图设置, 将标题, 图片, 状态和其他内容映射到笔记属性.
5. 使用 Bases 原生属性列表调整卡片中其他字段的显示顺序.
6. 根据需要设置卡片宽度, 文件打开方式和视图专属选项.

复杂视图建议先准备属性, 再建立映射. 未映射的可选字段不会阻止视图运行.

## 安装

### BRAT

使用 [BRAT](https://github.com/TfTHacker/obsidian42-brat) 添加:

```text
AlbusGuo/albus-more-bases-views
```

BRAT 安装标准插件文件后, 卡牌, 干员和炉石拓展包仍需从获得授权的独立分发渠道取得, 再通过对应视图的缺失提示导入.

### 手动安装

1. 从 [GitHub Releases](https://github.com/AlbusGuo/albus-more-bases-views/releases) 下载 `main.js`, `manifest.json`, `styles.css`, `LICENSE`, `THIRD_PARTY_NOTICES.md` 及随附的上游许可证文件.
2. 创建 `<Vault>/.obsidian/plugins/albus-more-bases-views/`.
3. 将插件文件与许可证文件放入该目录.
4. 如果已经从获得授权的渠道取得拓展包, 创建 `view-packs/` 子目录并将需要的 `.mbvpack` 放入其中; 也可以稍后从对应视图导入.
5. 重新加载 Obsidian.
6. 在 **设置 -> 社区插件** 中启用 `More Bases Views`.

升级插件时需要通过相同的授权渠道取得匹配版本的拓展包. 旧版本拓展包不会被新版本加载.

## 兼容性与隐私

- 最低支持 Obsidian `1.10.2`.
- 插件声明支持桌面端和移动端; 炉石, 干员与大型地图在桌面端拥有更充足的性能和显示空间.
- 插件不收集遥测数据, 不上传 Vault 内容, 也不会下载或执行远程代码.
- 项目视图在配置 GitHub 仓库后会向 `img.shields.io` 请求所选仓库指标.
- 地图视图会请求当前配置的地图瓦片; 默认使用 OpenStreetMap 与 CARTO.
- 笔记属性使用远程图片 URL 时, Obsidian 会访问对应图片地址.
- 炉石视图不附带专用字体. 未安装 `AR LisuGB`, `GBJenLei-Medium`, `BlizzardGlobal` 或 `BelweBT-Bold` 时会使用系统回退字体.

## 开发说明

项目使用 TypeScript, npm 与 esbuild. 功能代码位于 `src/`, `src/main.ts` 负责插件生命周期和视图注册.

```bash
npm install
npm run lint
npm run build
```

公开源码不包含 `assets/`. `npm run build` 在没有私有素材时仍会生成可运行的核心插件; 只有在本地存在完整私有素材时才会额外生成 `view-packs/`.

生产构建输出到 `dist/`:

```text
dist/
├─ main.js
├─ manifest.json
├─ styles.css
├─ LICENSE
├─ THIRD_PARTY_NOTICES.md
├─ POKEMON_CARDS_CSS_LICENSE
├─ OBSIDIAN_MAPS_LICENSE
├─ MAPLIBRE_LICENSE
└─ view-packs/                 # 仅在私有素材可用时生成
   ├─ card.mbvpack
   ├─ operator.mbvpack
   └─ hearthstone.mbvpack
```

提交修改前请运行 `npm run lint` 和 `npm run build`. `assets/`, `dist/`, `main.js` 与 `.mbvpack` 均不进入公开 Git 仓库.
